## 第三课：输入位置，复用完整抓放

双击 `run_coordinates.cmd`，或运行 `& '..\.venv\Scripts\python.exe' .\step03_coordinates.py`。

打开 `step03_coordinates.py`，主要改这两个变量：

```python
PICK_XYZ = [0.27, 0.07, 0.065]
PLACE_XYZ = [0.29, -0.10, 0.065]
```

它们表示方块初始中心和希望放下后的中心，均为世界坐标，单位米。本课仍是30毫米方块与同一张桌面，中心Z固定0.065米，不处理不同桌高或尺寸。

数据流：两个位置 → `PickPlaceRunner(..., pick_xyz=..., place_xyz=...)` → `DesktopSim`生成方块和蓝色标记 → 按坐标生成各阶段tool0路点 → IK转六轴角度 → 平滑执行与物理接触 → 用同一放置目标检查物体终点。

坐标是方块中心，不能直接当作tool0的抓取点：下降抓取时tool0在方块中心下20毫米；抬升与搬运时tool0的Z为0.15米；下降放置时，程序使用已夹住物体相对tool0的实际偏移来换算。

也可通过命令行覆盖这两个变量（每组三个数）：

```powershell
& '..\.venv\Scripts\python.exe' .\step03_coordinates.py --pick 0.28 0.05 0.065 --place 0.28 -0.12 0.065
```

无窗口验证加 `--headless`；结果在 `results/coordinates_<时间>/`，保留输入坐标、实际物体坐标和接触记录。非法数值、错误Z或桌外位置会被拒绝；桌面内的位置仍可能因IK不可达或碰撞而失败，执行会中止并保存阶段错误。

本课验收：先运行默认的一组新坐标，再运行上面的原坐标，观察方块与蓝色标记一起改变，机械臂能抓起、搬运、放稳；能解释为什么只改两个位置就能带动整套流程。仿真结果不代表真机验证。

### 运动速度由哪里决定

`pick_place.py` 中每次 `move_to(..., seconds)` 的最后一个时间参数决定该段用多久走完；相同路径用时越短，速度越高。入口 `step02_pick_place.py` 默认使用 `--speed fast`，把机械臂各段时间乘以0.5。夹爪开合时间和接触稳定等待保持原值。

| 阶段 | 原速 normal | 加速 fast |
| --- | ---: | ---: |
| 接近 | 5秒 | 2.5秒 |
| 下降抓取 | 3秒 | 1.5秒 |
| 抬升 | 3秒 | 1.5秒 |
| 搬运 | 4秒 | 2秒 |
| 下降放置 | 3秒 | 1.5秒 |
| 退让 | 2.5秒 | 1.25秒 |
| 含夹爪和等待的总时间 | 26.4秒 | 16.15秒 |

恢复原速：`& '..\.venv\Scripts\python.exe' .\step02_pick_place.py --speed normal`。也可以运行 `run_pick_place.cmd --speed normal`。

采用同形状的五次时间曲线时，时间减半，参考速度约增至2倍、加速度约4倍、jerk约8倍，因此不能无限缩短时间。当前fast档已完成完整接触抓放仿真验收；它不是经过搜索得到的最优速度，也不代表实机可用速度。仿真步长仍为2毫秒，保持原有物理积分精度。

无窗口运行：`& '..\.venv\Scripts\python.exe' .\step02_pick_place.py --headless`。

黄色方块保持自由刚体，靠夹指的物理摩擦接触被带起；无焊接约束、无运行中方块位置重置。机器人仍使用教学位置伺服和理想外部重力支持。

**验收**：两侧夹指接触→方块中心抬高至少6厘米→搬运到目标附近→松爪后方块在桌面目标区域停稳、与夹爪脱离。失败时保存错误和已有日志，不继续宣称成功。

完整任务结果保存到 `results/pick_place_<时间>/`：`pick_place_report.json`、`tracking.csv`、`task_trace.png`、各阶段场景图和 `scene.xml`。报告含物体起终点、最大离桌高度、双侧接触力、异常接触和最终通过状态。

### 重要的模型接口核对

原滑块间距与真实爪口方向相反。本项目已用碰撞网格几何核对并修正：真实开口约为 `0.10 - 滑块间距`，`set_gripper(0.07)` 表示张开70毫米。闭合指令平滑减小到26毫米，对30毫米方块形成夹持压力；实际开口会被物体阻挡在约30毫米。

`tool0_site` 比夹指最下端低约8.5毫米。当前方块的抓取参考点设在方块中心下方20毫米，保证夹指与侧面重叠、指尖仍高于桌面。抓取高度不是简单把tool0放到方块中心。

夹指和方块的接触参数使用6毫秒响应时间、摩擦系数1.2以支持稳定接触。这些是仿真设定，没有在实机上辨识。临时碰撞检查会预测被夹物体随手运动，但只修改检查用的scratch数据，不改实际仿真物体。

接近阶段使用平滑关节插值，末端路径不保证为直线；之后下降、抬升、平移和退让使用固定向下朝向的笛卡尔路点及连续IK。

## 第一课重点看哪几行

打开 `step01_hover.py`，依次看五步：

1. `CUBE_XYZ` 是物体中心的世界坐标，`HOVER_XYZ` 是末端目标坐标。
2. `solve_ik(sim, HOVER_XYZ, DOWN_ROTATION)` 将目标位置和向下姿态转换成六关节角。
3. `quintic_trajectory(...)` 从当前关节角平滑移动到 IK 解；此处复用五次时间曲线，先理解调用过程。
4. `execute(...)` 驱动模型、推进物理仿真并保存实际反馈。
5. 用实际关节状态做 FK，检查末端最终位置与姿态。

`scene.py` 和 `kinematics.py` 是目前复用的基础设施，先不要求逐行学习数值求解和渲染。

## 场景和坐标约定

- 世界坐标原点与机器人固定基座参考对齐，Z向上；位置用米。
- 桌面上表面高度：`0.05 m`。
- 黄色方块边长：`0.03 m`，初始中心：`[0.28, 0.05, 0.065] m`。
- 末端参考点：官方模型 `tool0_site`。目标：`[0.28, 0.05, 0.20] m`。
- 向下姿态：末端局部Z轴对齐世界-Z轴；局部X轴对齐世界-X轴。
- 蓝色圆形标记留作后续放置区域，本课不搬运。
- 方块是具有质量和自由关节的物体，会受重力和桌面接触影响。当前没有尝试抓取。

后续下降抓取前，需要核对夹指接触位置与 `tool0_site` 的偏移。本课“到物体上方”的验收不等于抓取验收。
